# Assets and hosting

The local CraftPix library owns immutable vendor source. `tools/import_craftpix.py` copies seven saber-fighter animation sheets and three RPG Game UI button states plus one 32×32 free prototype tile and the character/tile notices, into ignored `assets/private/`. The tracked manifest binds source and destination paths, PNG hashes and original archive hashes. `assets/craftpix-clips.json` records runtime frame indices after excluding effect-only tail cells; the importer needs Python 3 and Pillow. Runtime slices regions without changing originals. The importer records adoption in the private library under its mutation lock. Local subscription evidence remains in the library; none is copied here.

CraftPix raw art and PSDs must never enter public source. Code can run with the original fallback sprite. Exported playable game resources may contain licensed art according to game-use terms; there is no asset-download or artwork-export feature. Root notices identify the rights holder. No project license has been assigned.

`tools/build_web.sh` excludes its ignored build directory from Godot scanning with `.gdignore` and explicitly imports and exports using the managed Godot 4.7 Podman runtime. `play.sh` uses hardware GPU access and host networking for local co-op. The Web preset uses Compatibility, no threads or Web GDExtension, producing static files in ignored `build/web/`. The same export includes a separate portable core Wasm module and dependency-free loader, awaited before engine startup. Native core binaries and descriptor stay outside Web exports. GitHub Pages needs only these files at site root with `.nojekyll`. Web exports contain the runtime's generated JavaScript; project tooling needs no Node packages.

Source publication must exclude `.godot/`, private assets, candidate builds and capture files. Keep one current candidate; delete it after successful remote verification. Local preview image is disposable. Deployed assets belong in a separate Pages branch, never the source branch. `tools/deploy_pages.py` explicitly deploys a reviewed candidate via a temporary Git index, preserving the normal checkout; it verifies the configured GitHub origin and required output files. No automatic deployment workflow or credentials have been installed. The public repository is https://github.com/RaresKeY/coop-side-scroller and Pages serves https://rareskey.github.io/coop-side-scroller/ from `gh-pages` root.
