# Assets and hosting

The local CraftPix library owns immutable vendor source. `tools/import_craftpix.py` copies seven saber-fighter animation sheets and three RPG Game UI button states plus one 32×32 free prototype tile and the character/tile notices, into ignored `assets/private/`. The tracked manifest binds source and destination paths, PNG hashes and original archive hashes. `assets/craftpix-clips.json` records runtime frame indices after excluding effect-only tail cells; the importer needs Python 3 and Pillow. Runtime slices regions without changing originals. The importer records adoption in the private library under its mutation lock. Local subscription evidence remains in the library; none is copied here.

CraftPix raw art and PSDs must never enter public source. Code can run with the original fallback sprite. Exported playable game resources may contain licensed art according to game-use terms; there is no asset-download or artwork-export feature. Root notices identify the rights holder. No project license has been assigned.

`tools/build_web.sh` excludes its ignored build directory from Godot scanning with `.gdignore` and explicitly imports and exports using the managed Godot 4.7 Podman runtime. `play.sh` uses hardware GPU access and host networking for local co-op. The Web preset uses Compatibility, no threads or Web GDExtension, producing static files in ignored `build/web/`. The same export includes a separate portable core Wasm module and dependency-free loader, awaited before engine startup. The export embeds source/build identity before the bridge loads and writes `build-info.json` with gameplay payload hashes (see [diagnostics](diagnostics.md)); Pages publication requires this exact JSON filename and continues rejecting arbitrary JSON files. Native core binaries and descriptor stay outside Web exports. GitHub Pages needs only these files at site root with `.nojekyll`. Web exports contain the runtime's generated JavaScript; project tooling needs no Node packages.

Source publication must exclude `.godot/`, private assets, candidate builds and capture files. Keep one current candidate; delete it after successful remote verification. Local preview image is disposable. Deployed assets belong in a separate Pages branch, never the source branch. `tools/deploy_pages.py` explicitly deploys a reviewed candidate via a temporary Git index, preserving the normal checkout; it verifies the configured GitHub origin, Pages branch configuration and required output files. Build/export and publication share an exclusive Git-common-directory `web-publication.lock`, with a 20-minute acquisition limit. Publication fetches the actual remote parent without changing `FETCH_HEAD`, pushes an immutable commit with an explicit remote-tip lease, and never changes the shared local `gh-pages` branch or source index. An unchanged candidate reuses the remote commit instead of creating another deployment. The tool waits up to `--timeout` seconds (default 900) for that exact commit to report built, then verifies every hosted candidate file by SHA-256 with a separate bounded propagation wait (up to 180 seconds). Failed builds, deadlines and hash mismatches exit nonzero; a successful push alone is not reported as deployment success. API failures retry within the deadline. A queued/failed commit is left intact for inspection; the tool does not cancel jobs or automatically rerun deployments. Hosted browser verification remains a separate required check before cleanup. Offline deployment tests run with `python3 -m unittest discover -s tests -p test_deploy_pages.py`. No automatic deployment workflow or credentials have been installed. The public repository is https://github.com/RaresKeY/coop-side-scroller and Pages serves https://rareskey.github.io/coop-side-scroller/ from `gh-pages` root.

Local environment files (`.env`, `.env.*` except `.env.example`) and private-key extensions (`.pem`, `.key`) are ignored as an accidental-staging guard. This does not remove previously tracked secrets; run `tools/audit_publication.py` before pushing. Private configuration stays outside the checkout.

## Firebase Hosting mirror

The separate Firebase project and default Hosting site are `ember-bridge-playtest`, published at https://ember-bridge-playtest.web.app/. Project-owned `firebase.json` deploys only compiled `build/web` assets with no-cache responses and the Wasm MIME type. Use the installed standalone CLI: `firebase deploy --only hosting --project ember-bridge-playtest --config firebase.json --non-interactive`. The existing Cloudflare issuer allows this exact origin and its Firebase default alias; existing GitHub and localhost origins remain supported. No billing, database, Functions or App Hosting setup is required by this static deployment.
