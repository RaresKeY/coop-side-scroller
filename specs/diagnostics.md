# Connection diagnostics

Owners: `src/diagnostics.gd`, hooks in `src/main.gd` / `src/private_lobby.gd`, browser route helper in `adapters/web/ember_core_bridge.js`, `server/turn/worker.mjs`, and the external Cloudflare operator's `worker-logs` command.

Each browser lobby entry or new manual connection attempt gets a random 16-hex diagnostic ID. Lobby requests carry it separately from seat credentials. Browser reports identify schema `diagnostics-v3` (the local endpoint also accepts `diagnostics-v1` and `diagnostics-v2`) and retain the last 64 sequential events in memory: elapsed time, role, room ID, requested route, HTTP action/status/allowlisted error, connection state, tab visibility, failure category and aggregate RTT/RPC/snapshot-gap/actor counters. The browser helper records ICE gathering/connection state transitions, numeric ICE-server error codes and server scheme only, local candidate counts by type, candidate-pair counts by outcome and aggregate checks sent/responses received. It samples unconnected peers every two seconds, drains metadata every 500 ms and captures buffered events before failure teardown, so failed attempts can be investigated. Connected peers also expose selected candidate types, candidate protocol and RTT. V3 transport events additionally include `relayProtocol` (UDP/TCP/TLS/unknown), `relayPort` (443 only when identified from the selected Cloudflare TLS URL; otherwise 0), selected-pair byte/packet totals and per-second rates, plus separately named `transportBytes*` / `transportPackets*` totals and rates for the complete ICE transport. A selected pair can report zero inbound bytes despite working gameplay; its counters must not be interpreted as whole-transport traffic. Rates use counter deltas and browser stats timestamps; first samples, unavailable counters, counter resets and pair changes report -1 instead of invented rates; transport counters retain a separate baseline keyed by transport identity. Missing RTT is -1. These are WebRTC stats, not all router traffic or billed bytes. Candidate UDP does not imply the browser-to-TURN leg uses UDP. The client initially uploads v3. Only an explicit HTTP 400 `invalid_diagnostics` response switches that page to legacy v2 and retries once; network/auth/service failures do not downgrade. Legacy uploads omit extended transport fields, browser network events and build context, which remain in copied local reports. The current public Worker still uses v2; v3 collection requires publishing the prepared Worker update. Missing/closed-peer stats are reported as unavailable. Each helper sample completes its callback once, with JSON null when unavailable or superseded. The Godot collector allows one sample in flight, retains the callback until completion and captures the requesting role. Out-of-order completions cannot replace a newer route/counter baseline. The helper queue is bounded to 64 events; old peers and delayed old samples cannot contaminate a replacement attempt. A 701 server error is an observation of that server attempt, not a claim that every route failed or a diagnosis of NAT type. No SDP, candidate addresses, access keys, seat tokens, room names, inputs or arbitrary error messages enter reports. Snapshot gaps are not a general packet-loss measurement.

Web exports embed `EmberBuildInfo` and write `build-info.json`: full source HEAD, dirty-worktree flag, UTC build time and SHA-256 of a canonical sorted map of the exported PCK, engine JS/Wasm, core bridge/Wasm and audio-worklet hashes. The manifest and HTML are excluded from this digest to avoid a circular hash. This identifies the gameplay payload, not the complete hosting configuration or an attested source build. Metadata is never fetched at runtime, so an old open tab retains its own build identity. V3 context includes this metadata plus allowlisted site (`firebase`, `pages`, `local`, `other`) and synthetic-test (`none`, `runpod`, `browser`) labels; no arbitrary hostname/URL is recorded. Test markers are self-reported, not authentication. Unknown metadata is explicit. Browser `navigator.onLine` is sampled on entry and transitions; it is only a browser connectivity hint and cannot prove ISP reachability. V3 `lobby_end` records whether polling ended after both peers acknowledged (`complete`) or after an error once connected (`error_after_connected`). Failure events record the explicit code-path `source`, the pre-teardown WebRTC `state` and sticky lobby `established` flag. Sources distinguish multiplayer connection failure/disconnect, terminal RTC state, disconnect/connect/gather timeouts, lobby setup errors and other setup failures. These fields are stripped for legacy v2 uploads; no arbitrary error text is accepted. Lobby response attribution captures the request's original diagnostic ID and discards responses belonging to replaced attempts.

The menu's **Copy connection diagnostics** uses the existing acknowledged clipboard/fallback dialog. Reports survive returning to Menu until the next attempt. Failure messages include the diagnostic ID. Authenticated uploads to `/v1/diagnostics` occur on connection-state changes, failures, leave and 15-second active-game summaries, with one request in flight, an eight-second timeout and at most 240 attempted batches per attempt. Reports are best effort; abrupt tab closure, suspension, expired access and lost internet can prevent delivery. The copyable memory buffer remains useful when uploading fails. Successful batch acknowledgement advances a sequence watermark; later events remain pending.

The endpoint shares the exact Origin allowlist and invitation gate but uses separate rate-limit bindings (20/minute/IP, 120/minute/shared). These are per-location limits, not global budget caps. Malformed report bodies return HTTP 400; journal/service failures return HTTP 503. Strict schema validation rejects unknown fields, arbitrary text, oversized histories and invalid values. Playtest-key holders can submit reports but cannot read stored reports. Browser reports are untrusted diagnostics, not authenticated player identity.

The existing `PrivateLobbies` Durable Object holds a separate journal key, bounded to 256 entries and 256 KiB total, with a seven-day maximum age. Capacity eviction can remove entries earlier. Routine successful directory polls and empty syncs do not occupy the journal. Meaningful lobby actions, signaling publication, readiness, failures and cleanup reasons are retained, alongside browser batches. Room deletion does not delete the journal. Reads and alarms exclude/prune old entries. The next alarm is the earliest absolute room deadline, host/guest lease deadline or journal retention deadline; unrelated traffic cannot postpone it. No additional service or namespace is provisioned. This retention does not describe provider backup retention.

Structured console events also go to enabled Cloudflare Workers Logs; automatic invocation logs are disabled to minimize request metadata. Provider retention/usage remains separate from the journal. Account API log-query access was rejected with HTTP 403; working retrieval therefore uses the private journal, not the Observability API.

Operator reads use a separate random secret in owner-only `~/.config/cloudflare-api/diagnostics-coop-side-scroller-issuer.json`, deployed as `DIAGNOSTIC_READ_TOKEN`. This key is never given to browsers/testers. The existing containerized operator reads it privately:

```sh
cd ~/workspace/tooling/cloudflare-api
./cloudflare worker-logs coop-side-scroller-issuer --minutes 60
./cloudflare worker-logs coop-side-scroller-issuer --attempt 0123456789abcdef --minutes 1440
```

From the game checkout, `python3 tools/read_diagnostics.py [--attempt ID] [--minutes 60]` saves sanitized evidence to ignored `build/diagnostics-latest.json`.

Attempt lookup includes related room events while those links remain in the journal. Output contains sanitized structured diagnostics and can be redirected to ignored `build/` evidence. The read endpoint uses the same rate bounds and currently requires the playtest invitation period to remain valid. Deployments preserve the private read secret. No paid-plan or token-permission change is made.

Tests: `deno test --no-config --allow-read=adapters/web/ember_core_bridge.js tests/ice_diagnostics.test.js`, `./tests/web.sh --ice-diagnostics-check` (real unreachable STUN server with server-error or zero-candidate gathering evidence, unconnected-peer stats, upload and metadata redaction), `server/turn/diagnostics.test.mjs`, journal cases in `server/turn/lobby.test.mjs`, and `tests/connections.sh`.
