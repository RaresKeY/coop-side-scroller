# Godot reference prototype

`src/main.gd` owns onboarding/menus, keyboard capture, transport, clocks, lab hooks, asset playback and rendering of a single-screen tile floor and training dummy. The portable C++ library owns simulation, movement/combat, automatic animation states/events, authority and snapshot synchronization. Read [portable-core.md](portable-core.md) before changing those rules and [c-abi.md](c-abi.md) before changing messages or the ABI. `adapters/godot/portable_core.gd` is the only gameplay bridge; there is no GDScript fallback solver.

During play, only Menu, connection status and movement instructions are shown. Native Play solo / Host game / Join game and address entry live in the menu. Browser menus expose Play solo and Private rooms, with manual code pairing behind an advanced toggle. The private lobby handles discovery and setup automatically. Open setup panels suppress gameplay input. No animation selection controls exist. The renderer maps authoritative enum states to idle/run/jump/attack/walk clips, restarts attacks by replicated attack ID and shows damage feedback from core events. Hurt/death sheets are retained for future authored gameplay states but not selectable.

Character presentation is 1×, about two floor tiles tall. Runtime atlas regions preserve attack blades crossing cell boundaries, frame-aware anchors prevent unwanted offsets, and a small shader emulates 8× nearest-copy/linear sampling without enlarged assets. Attack and jump playback follow the actual windup/contact/recovery and ascent/apex/descent/landing phases. See [character presentation](character-presentation.md) for exact anchors, timings and full-scene frame verification. The 32×32 floor is presentation for the core ground plane. No RPG inventory, map system, engine collision integration or audio is included.

Native: a minimal C-interface GDExtension loads from current ignored `build/native/`; ENet carries byte payloads, with UDP 27840 by default and ephemeral local-pair ports. Browser: `adapters/web/ember_core_bridge.js` awaits an import-free core Wasm module before Godot starts; JavaScriptBridge calls the same C ABI numeric helper. Godot's separate Wasm engine memory never receives a pointer into the core's memory. Build/runtime boundaries are in [build-targets.md](build-targets.md).

The transport adapter uses one `gameplay_message(PackedByteArray)` RPC over ordered unreliable delivery and maps actual connected peer IDs to core slots 1/2. It does not encode/decode gameplay rules or snapshots. The core emits periodic binary snapshots and sequenced input packets. Ping/pong, RTT, artificial delay queues, connection timeout and peer membership callbacks remain outside the core. Stable core actor slot 2 is independent of ENet's allocated peer ID. Render dictionaries are copied views, never authority sources.

WebRTC uses authenticated private lobby signaling, protected Cloudflare temporary TURN credentials, and optional direct-only Google STUN. Manual SDP/ICE remains an advanced fallback. Browser relay co-op passes movement/combat with independent cores; broader NAT/browser acceptance is still limited. Gathering/connection failures return to setup. See [private lobbies](private-lobbies.md), [browser connection](browser-connection.md), and [TURN service](turn-service.md) for exact contracts and evidence.

`--test-host` / `--test-client` are finite native integration modes. `--capture` saves a finite native gameplay preview. See [network lab](network-lab.md) and [verification](verification.md) for interactive testing and actual evidence.
